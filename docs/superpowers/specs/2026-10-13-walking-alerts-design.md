# 걸을 때만 알리기: 설계

날짜: 2026-10-13 · 브랜치: `walking-alerts`

## 목표

차량(버스, 택시)으로 저장한 장소나 쿠폰 지점을 지나갈 때는 알림을 울리지 않고 미뤄 둬요. 그 근처에서 내려 걷기 시작하면 그때 알려요.
"울리면 지금 들를 수 있는 곳"이라는 믿음을 주는 게 목적이에요. 알림이 쓸데없이 쌓이면 사람들은 알림을 꺼 버리니까요.

### 사용자와 정한 것
- 차량이면 알림을 미뤘다가, 근처에서 걸으면 알려요. 그냥 넘기거나 조용한 알림으로 보내지 않아요.
- 차량이면 **3분 뒤** 다시 확인해요.
- 영업시간은 알 방법이 없어서(카카오 로컬 API가 주지 않음) 이번 범위에서 빼요.

### 범위 밖
- 영업시간으로 거르기
- Activity Recognition API (권한이 하나 더 필요해서 속도 기준으로 대신해요)

### 앱이 화면에 떠 있을 때 (사용자 요청: 정신없게 울리지 않기)
- 앱이 화면에 보이는 동안에는 시스템 알림을 띄우지 않아요. 목록의 노란 "지금 근처예요" 띠와 지도의 노란 표시가 그 역할을 해요.
- 이때는 쿨다운도 기록하지 않아요. 앱을 닫은 뒤 다시 반경에 들어가면 평소처럼 알려요.
- 그래서 앱 안 감시(`HomeViewModel`이 위치가 바뀔 때마다 `onPlaceEnter`를 부르던 부분)는 더 할 일이 없어 지워요.
- 구현: `AppContainer`에 앱이 화면에 보이는지 나타내는 값을 두고, 화면의 `ON_RESUME`/`ON_STOP`에서 바꿔요. `AlertService`는 이 값이 참이면(그리고 `force`가 아니면) 알리지 않아요. 쿠폰 화면의 "알림 테스트"는 `force`라 그대로 울려요.
- 미뤄 둔 알림을 다시 확인할 때 앱이 화면에 떠 있으면 보류를 지우지 않고 남겨 둬요. 1km 거리의 장소는 "지금 근처예요" 반경 밖이라 화면에도 안 보이기 때문이에요. 앱을 닫으면 다음 재확인에서 알려요(30분 제한은 그대로).

### 이동 중의 감시 창 갱신
- 바뀌지 않아요. 차량으로 이동하는 중에도 1km 갱신 구역을 벗어날 때마다 앱이 깨어나 그 자리에서 지켜볼 곳을 다시 골라요. 이번 변경은 진입했을 때 바로 알릴지 미룰지만 정해요.

## 판단 기준

- **차량 판단**: 지오펜스 진입 이벤트에 딸려 오는 위치(`GeofencingEvent.triggeringLocation`)의 속도가 **4.2m/s(시속 15km) 이상**이면 차량으로 봐요.
  - 걷기는 1.4m/s 안팎, 시내버스는 평균 5~8m/s예요.
  - 속도 정보가 없으면(와이파이 위치 등) 걷는 것으로 보고 지금처럼 바로 알려요. 알림을 놓치는 쪽보다 한 번 더 울리는 쪽이 낫다는 판단이에요.
- **재확인**: 미룬 지 3분 뒤 위치와 속도를 한 번 얻어 이렇게 판단해요.
  - 목표 지점에서 **1km 안**이고 차량 속도가 아니면 → **알림**
  - 아직 차량 속도이거나 위치를 못 얻었고, 미룬 지 **30분 안**이면 → **3분 뒤 다시 확인**
  - 그 밖(1km 밖에서 걷는 중, 30분 지남) → **버림**
  - 최대 확인 횟수는 10번이에요(30분 ÷ 3분).
- 버린 뒤에도 그 장소의 지오펜스는 그대로 등록돼 있어요. 나중에 걸어서 반경에 들어가면 평소처럼 알림이 와요. 미루기는 "근처에서 내렸지만 200m 반경 안까지는 안 들어온" 경우를 위한 장치예요.

## 구성

| 단위 | 파일 | 하는 일 |
|---|---|---|
| 순수 판단 | `core/Pending.kt` | `isVehicleSpeed(speed)`, `PendingAlert`, `decidePending(p, here, speed, now)` → `Alert` / `Recheck` / `Drop`, 같은 대상의 보류 합치기 |
| 저장 | `data/PendingStore.kt` | `pending.json`에 보류 알림 목록 저장. 계약 파일인 `Repository.kt`는 건드리지 않아요 |
| 진입 처리 | `geofence/GeofenceReceiver.kt`, `GeofenceWorker.kt` | 이벤트 위치의 속도를 작업 입력으로 넘겨요. 차량이면 알리지 않고 보류로 저장한 뒤 재확인을 예약해요 |
| 재확인 | `geofence/RecheckWorker.kt` | 3분 뒤 실행돼 위치·속도를 얻고 `decidePending`대로 알리거나, 다시 예약하거나, 버려요 |
| 알림 | `notify/AlertService.kt` | 기존 `onPlaceEnter` / `onBranchEnter`를 그대로 써요. 쿨다운도 그대로 적용돼요 |

### 데이터

```kotlin
@Serializable
data class PendingAlert(
    /** 장소 id 또는 지점 지오펜스 id("b|<brandKey>|<kakaoId>"). */
    val regionId: String,
    /** 같은 대상끼리 합치는 기준: 장소는 장소 id, 쿠폰은 브랜드 키. */
    val group: String,
    val latitude: Double,
    val longitude: Double,
    /** 처음 미룬 시각. 30분 제한의 기준이에요. */
    val since: Long,
)
```

버스로 스타벅스 지점 세 곳을 연달아 지나가면 보류도 세 개가 생겨요. 같은 `group`은 하나로 합치고, 위치는 가장 최근에 지난 지점으로 바꿔요. `since`는 처음 값을 유지해요.

### 흐름

```
지오펜스 진입 (앱이 꺼져 있어도)
  → GeofenceReceiver: 이벤트 위치의 속도를 작업 입력에 담음
  → GeofenceWorker
       ├─ 속도가 차량 아님(또는 모름) → 지금처럼 바로 알림
       └─ 차량 → PendingStore에 저장(같은 group은 합침) → RecheckWorker를 3분 뒤로 예약
RecheckWorker (3분마다, 고유 작업 하나)
  → 보류 목록과 현재 위치·속도
  → 보류마다 decidePending
       ├─ Alert   → AlertService로 알리고 목록에서 뺌
       ├─ Recheck → 목록에 남김
       └─ Drop    → 목록에서 뺌
  → 목록이 남아 있으면 3분 뒤로 다시 예약
```

재확인 작업은 보류 개수와 상관없이 하나만 돌아요(`enqueueUniqueWork("recheck", KEEP)`). 위치는 한 번에 한 번만 얻어요. 이때 와이파이·기지국 위치가 안 잡히면 GPS로 한 번 더 시도해요(`LocationTracker.current()`와 같은 방식).

## 에러와 예외

- 재확인 중 위치를 못 얻으면 → 그 회차는 다시 확인(30분 제한 안에서). 30분이 지나면 버려요.
- 앱을 업데이트하거나 기기를 재부팅해서 예약된 작업이 사라져도 WorkManager가 작업을 복원해요. 보류 목록은 파일에 있어서 남아 있어요.
- 보류된 장소를 사용자가 지웠거나 쿠폰을 다 썼다면 → `AlertService`가 대상을 못 찾거나 쓸 쿠폰이 없어서 알리지 않고, 보류는 목록에서 빠져요.

## 테스트

- `core/Pending.kt` 단위 테스트
  - 속도 경계(4.1 / 4.2m/s, 속도 없음)
  - `decidePending`: 1km 안에서 걷기 → 알림, 차량 + 30분 안 → 재확인, 30분 지남 → 버림, 1km 밖에서 걷기 → 버림, 위치 없음 → 재확인/버림
  - 같은 group 합치기: `since` 유지, 위치 갱신
- 시뮬레이터(`SimulateWindow`)
  - 지금 앱이 버스 이동 중에 울리는 알림 수를 "버스로 지나가며 울린 알림"으로 함께 표시해요. 이번 변경으로 없어지는 알림의 양이에요.
- 에뮬레이터
  1. 성수 근처 장소를 저장하고 앱을 종료해요.
  2. 모의 위치를 차량 속도로 옮겨 그 장소를 지나가요. 알림이 오지 않고 `pending.json`에 보류가 생기는지 확인해요.
  3. 장소에서 500m 떨어진 곳에 멈춰 천천히 걸어요. 3분쯤 뒤 알림이 오는지 확인해요.
  4. 다른 경우로, 지나간 뒤 계속 차량 속도로 멀어지면 알림 없이 보류가 사라지는지도 확인해요.
  - 에뮬레이터의 `geo fix`는 속도를 직접 넣을 수 없어서, 위치 간 거리와 시간으로 속도가 계산되는지 먼저 확인해야 해요. 안 되면 모의 위치 제공자(`adb shell cmd location providers set-test-provider-location`)로 속도를 넣어요.
