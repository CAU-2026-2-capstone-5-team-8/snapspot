# 동네 묶음: 설계

날짜: 2026-10-13 · 브랜치: `feature/neighborhood-bundles`

## 목표

한 동네에 저장해 둔 장소가 여러 곳이면 하나의 "묶음"으로 보여 줘요.
- **홈**: "성수동 · 가 볼 곳 4곳" 카드를 보여 주고, 카드를 누르면 모두 들르는 최단 걷기 동선을 지도에 그려요.
- **알림**: 그 동네에 들어가면 장소마다 울리던 알림 대신 묶음 알림을 한 번만 보내요.

### 사용자와 정한 것
- 홈에서 보기와 그 동네에 가면 알림 한 번, 둘 다 해요.
- 묶는 방법은 **거리로 묶고, 이름은 행정동으로** 붙여요.
- **알림에는 경로 정보(걷는 시간, 동선)를 넣지 않아요.** 최단 경로는 홈에서만 봐요.
- 동선은 **최단 거리**로 구해요.

### 범위 밖
- 실제 도로를 따라가는 길찾기 (길찾기 API가 유료라서 직선 거리로 계산)
- 쿠폰 지점으로 묶음 만들기 (묶음은 저장한 장소로만 만들어요. 쿠폰 지점은 동선에 "들를 곳"으로만 더해요)
- 사용자가 묶음을 직접 편집하기

## 규칙

### 묶기 (`core/Bundles.kt`)
- 끝난 팝업(`placeEnded`)을 뺀 저장한 장소를 대상으로 해요.
- 두 장소 사이 직선 거리가 **700m 이하**면 같은 묶음으로 이어요. 사슬처럼 이어져요(A–B, B–C가 700m 이하면 A, B, C가 한 묶음).
- **3곳 이상**인 무리만 묶음이 돼요. 2곳 이하는 묶음 없이 지금처럼 장소 하나씩 다뤄요.
- 묶음 순서: 내 위치에서 가까운 순(위치를 모르면 장소가 많은 순).
- 묶음 id는 묶음 안 장소 id 중 가장 작은 값이에요. 장소가 더해지거나 빠지면 id가 바뀔 수 있는데, 묶음은 매번 다시 계산하니 괜찮아요.

### 쿠폰 쓸 곳 포함 (사용자 추가 요청)
- 묶음 카드에 "쿠폰 쓸 곳 포함" 스위치를 둬요. 기본은 꺼짐이에요.
- 켜면, 쓸 수 있는 쿠폰이 있는 브랜드(`isActive`) 가운데 묶음 장소 어느 곳에서든 500m 안에 지점이 있는 브랜드를 동선에 더해요.
- 브랜드마다 **지점 하나만** 들르면 돼요. 후보는 그 500m 안 지점들이고, 묶음 중심에서 가까운 순으로 최대 8곳이에요. 어느 지점을 들를지는 동선이 가장 짧아지도록 알고리즘이 골라요.
- 지점 후보는 기존 지점 검색(`nearbyBranches`, 격자 칸 캐시)으로 묶음 중심 기준으로 받아요. 받는 중이거나 실패하면 장소만으로 동선을 보여 주고, 카드에 "쿠폰 지점을 불러오지 못했어요"를 적어요.
- 지도에는 고른 지점만 동선 번호와 함께 보여요. 목록에는 "스타벅스 성수역점 (쿠폰)"처럼 표시해요.

### 최단 동선 (`core/Route.kt`)
- 문제를 **일반화 외판원 문제(Generalized TSP)**로 풀어요. 들를 곳은 "무리"예요. 저장한 장소는 후보가 1곳인 무리, 쿠폰 브랜드는 후보 지점이 여러 곳인 무리예요. 무리마다 정확히 한 곳을 들러요. 쿠폰을 넣지 않으면 모든 무리가 1곳짜리라 보통의 외판원 문제와 같아요.
- 입력은 출발점(선택)과 장소 좌표들, 출력은 방문 순서와 총거리(m)예요. 돌아오는 길은 빼요.
- **출발점**: 내 위치가 묶음 안 어떤 장소와도 1km 이내면 내 위치에서 출발해요. 아니면 총거리가 가장 짧아지는 장소에서 출발해요(출발점 없이 모든 시작점을 비교).
- **방법** (출발점이 있고 돌아오지 않는 열린 경로, g = 무리 수, N = 전체 후보 수):
  - **정확**: Held-Karp 동적 계획법을 무리로 넓혀요. 상태는 (들른 무리 집합 비트마스크, 마지막으로 들른 후보), 시간 O(2^g·N²), 메모리 O(2^g·N). 출발점이 없으면 모든 후보를 출발 상태로 놓아요. 무리가 모두 1곳짜리면 보통의 Held-Karp(O(n²·2ⁿ))와 같아요.
  - **근사**: 가까운 곳부터 잇기(아직 안 들른 무리의 후보 중 가장 가까운 곳)로 시작해, 아래 두 단계를 더 줄어들지 않을 때까지 번갈아 해요.
    - 순서 개선: 고른 후보를 고정하고 2-opt(구간 뒤집기)와 Or-opt(1~3곳 옮기기)
    - 후보 다시 고르기: 무리 순서를 고정하고, 각 무리에서 어느 후보를 고를지 층 그래프 최단 경로(동적 계획법, O(Σ kᵢ·kᵢ₊₁))로 한 번에 최적화
  - **검증 기준**: 완전 탐색(무리 순서 × 후보 선택 전부). 앱에서는 쓰지 않고 테스트와 실험의 정답 확인용으로만 써요.
  - **최적성 하한**: 무리 사이 거리를 "두 무리 후보끼리의 최소 거리"로 둔 그래프(출발점은 1곳짜리 무리)의 최소 신장 트리(MST, Prim)는 어떤 경로보다도 짧거나 같아요. 그래서 정답 없이도 근사의 오차 상한(근사 ÷ MST − 1)을 보여 줄 수 있어요.
  - **정확/근사 전환 기준 `EXACT_MAX`**(무리 수): 아래 실험에서 정확한 방법이 50ms를 넘기 직전의 g로 정해요(후보가 많을수록 느려지니 쿠폰 2개 × 8곳 기준으로 재요). 정하기 전 임시값은 10이에요.
- **걷는 시간**: 직선 거리 × 1.3(길이 굽은 정도) ÷ 분당 70m, 분 단위 올림. 홈 화면에만 보여요.

### 알고리즘 실험 (`-ProuteBench`)
- 시뮬레이터처럼 옵션을 줄 때만 돌아요: `./gradlew :app:testDebugUnitTest -ProuteBench -ProuteWrite`.
- 데이터: 시뮬레이션용 실제 서울 장소(`sim/seoul.json`, 동네마다 20곳). 동네 하나를 골라 그 안에서 n곳을 무작위로 뽑고, 출발점은 동네 중심 근처 임의 위치예요. n = 4…20, n마다 30번 반복(시드 고정).
- 쿠폰 실험: 동네에서 장소 5~8곳과 실제 쿠폰 브랜드 지점(묶음 장소에서 500m 안, 브랜드 1~2개, 브랜드마다 최대 8곳)을 뽑아요. 비교할 것:
  - **단순 방법**: 브랜드마다 묶음 중심에서 가장 가까운 지점을 미리 하나 골라 두고 보통의 최단 경로를 구하기
  - **지점 선택 최적화(GTSP)**: 정확한 방법
  - 지점 선택을 최적화하면 동선이 평균 몇 % 줄어드는지, 실행 시간이 얼마나 느는지
- 잴 것:
  - 실행 시간(중앙값, JVM 예열 후): 완전 탐색(n ≤ 9), Held-Karp(n ≤ 16), 근사(모든 n)
  - 근사의 최적 대비 오차: n ≤ 12는 Held-Karp 정답과 비교, 그보다 크면 MST 하한과 비교한 오차 상한
  - 근사 단계별 효과: 가까운 곳부터 잇기만 / + 2-opt / + Or-opt
- 결과: `docs/route.md`(알고리즘 설명, 복잡도 표, 결과 표, 쿠폰 지점 선택 비교 표)와 그래프 2개(`docs/route/time.svg` n별 실행 시간 로그 축, `docs/route/gap.svg` n별 오차). 그래프는 시뮬레이션과 같은 `SvgChart`로 그려요(로그 축 추가).
- `EXACT_MAX`는 이 결과로 정하고, 문서에 근거를 적어요.

### 동네 이름
- 묶음 중심(장소 좌표 평균)을 카카오 `GET /v2/local/geo/coord2regioncode.json`에 물어 행정동(`region_type = H`)의 `region_3depth_name`을 받아요.
- 행정동 이름의 숫자 부분을 떼서 사람들이 부르는 이름으로 바꿔요. 끝의 `숫자(·숫자)*가숫자*동` 또는 `숫자동`을 "동"으로 바꿔요.
  - "성수2가1동" → "성수동", "역삼1동" → "역삼동", "종로1·2·3·4가동" → "종로동", "연남동" → "연남동"(그대로)
  - 바꾼 결과가 "동" 한 글자면 원래 이름을 그대로 써요.
- 받은 이름은 약 1km 격자 칸(기존 `cellOf`) 단위로 `data/RegionNames.kt`(`region-names.json`)에 저장해 두고 다시 써요. 계약 파일은 건드리지 않아요.
- 이름을 못 받으면(네트워크 오류, REST 키 없음) "어니언 성수 근처"처럼 묶음에서 첫 장소 이름 + "근처"로 대신해요.

### 묶음 알림 (`notify/AlertService.kt`)
- 저장한 장소의 반경 진입(지오펜스, 또는 미뤄 둔 알림의 재확인)에서 그 장소가 묶음에 속하면 이렇게 해요.
  - 장소 알림 대신 묶음 알림을 보내요.
    - 제목: "📍 성수동에 가 볼 곳 4곳이 있어요"
    - 본문: 들어간 장소를 먼저, 나머지는 가까운 순으로 "어니언 성수, 무비랜드 외 2곳"
    - 경로 정보는 넣지 않아요.
  - 쿨다운: 묶음 안 장소 가운데 6시간 안에 알린 곳이 하나라도 있으면 울리지 않아요. 보내면 묶음 안 장소 모두에 알린 시각을 기록해요(`repo.markPlaceNotified`). 같은 동네를 걷는 동안 장소마다 또 울리지 않아요.
  - 앱이 화면에 떠 있으면 울리지 않는 규칙, 차량이면 미루는 규칙은 그대로예요.
- 묶음에 속하지 않은 장소는 지금처럼 장소 알림이에요.
- 딥링크는 `snapspot://bundle/<들어간 장소 id>`예요. 앱은 그 장소가 속한 묶음을 다시 계산해서 홈에 그 묶음 카드를 펼쳐 보여 줘요. 그사이 묶음이 사라졌으면 장소 딥링크처럼 그 장소에 초점을 맞춰요.
- 묶음 알림 이름에는 저장된 이름만 써요. 알림을 보내는 순간 카카오를 부르지 않아요. 저장된 이름이 없으면 대체 이름을 써요.

### 홈 화면
- 장소 탭 맨 위에 묶음 카드를 가로로 넘겨 볼 수 있게 놓아요. 카드에는 "성수동", "가 볼 곳 4곳", 걷는 시간 "약 25분"을 보여 줘요.
- 카드를 누르면 펼친 상태가 돼요.
  - 지도: 동선을 선(2px)으로 잇고, 장소 핀에 방문 순서 번호를 붙여요. 지도는 묶음 전체가 보이게 맞춰요.
  - 목록: 묶음 장소들을 방문 순서대로 보여 줘요.
  - 다시 누르거나 닫으면 원래 화면으로 돌아가요.
- 묶음 카드가 화면에 보이는 동안 동네 이름이 저장돼 있지 않으면 그때 카카오에 물어 저장해요.

## 테스트

- `core/Bundles.kt`
  - 700m 사슬 연결(A–B 600m, B–C 600m, A–C 1.2km → 한 묶음)
  - 3곳 미만은 묶지 않음
  - 700m 경계(700m는 이어지고 701m는 끊김)
  - 끝난 팝업 제외, 정렬 순서, 묶음 id
- `core/Route.kt`
  - 무리(후보 1~3곳) 3~7개 무작위 예시에서, 정확한 방법의 총거리가 완전 탐색과 같은지
  - 동선을 줄이는 지점을 고르는지(멀리 있는 지점 대신 경로 옆 지점)
  - 후보 다시 고르기가 거리를 늘리지 않는지
  - 8곳 이하 무작위 예시 여러 개에서, Held-Karp 총거리가 완전 탐색과 같은지
  - 근사 결과가 Held-Karp보다 짧지 않고, MST 하한보다 길거나 같은지
  - 2-opt, Or-opt가 거리를 늘리지 않는지
  - 출발점 있음/없음
  - 1곳, 2곳 같은 작은 입력
  - 11곳 이상 근사 결과가 가까운 곳부터 잇기만 한 결과보다 길지 않은지
  - 걷는 시간 계산
- 동네 이름 정리 규칙: "성수2가1동"→"성수동", "성수1가2동"→"성수동", "연남동"→"연남동", "역삼1동"→"역삼동", "종로1·2·3·4가동"→"종로동"
- `AlertService`
  - 묶음 장소 진입 → 묶음 알림 한 번, 묶음 장소 모두 쿨다운
  - 같은 묶음의 다른 장소 진입 → 울리지 않음
  - 묶음 아닌 장소 → 장소 알림
  - 화면이 떠 있으면 울리지 않음
- 에뮬레이터: 성수 장소 4곳 저장 → 앱 종료 → 걸어 들어가기 → 묶음 알림 한 번 → 누르면 홈 묶음 카드 → 카드 누르면 번호 붙은 동선
